# P1-15 Audit Report: Explicit, Validated, and Persisted Simulation Settings

**Issue ID:** P1-15  
**Canonical Title:** Simulation settings are too hard-coded  
**Canonical Problem Statement:** Make simulation settings explicit, validated and persisted per candidate rather than relying on hidden fixed defaults.  
**Acceptance Criteria:** Every simulated candidate records its explicit, validated simulation settings (region, universe, neutralization, decay, delay, truncation, unit_handling, pasteurization, nan_handling, max_trade/max_position); settings are validated against dataset and platform schemas before dispatch; candidate-level overrides are supported without hidden hardcoded fallbacks.  
**Status:** 🔍 **AUDITED — PENDING IMPLEMENTATION APPROVAL**  
**Affected Subsystems:** `alpha_harness.orchestrator.researchers`, `alpha_harness.brain.schemas`, `alpha_harness.brain.settings_schema`, `alpha_harness.discovery.catalog`, `alpha_harness.db.models`

## 1. Verified Code Findings vs. Architectural Hypotheses

### 1.1 Verified Code Findings (Ground Truth in Active Codebase)

1. **Fixed Session-Level Fallbacks in Candidate Creation**:
   - Location: [`alpha_harness/orchestrator/researchers.py:L327-334`](backend/src/alpha_harness/orchestrator/researchers.py) and [`L415-424`](backend/src/alpha_harness/orchestrator/researchers.py):
     ```python
     region = res_session.region or "USA"
     universe = res_session.universe or "TOP3000"
     delay = res_session.delay or 1
     session_constraints = res_session.constraints or {}
     neutralization = session_constraints.get("neutralization") or "INDUSTRY"
     decay = int(session_constraints.get("decay") or 4)
     ```
   - Evidence: When a research session leaves fields unset, universal hardcoded defaults (`"USA"`, `"TOP3000"`, `1`, `"INDUSTRY"`, `4`) are silently assigned to every candidate. Candidates generated by distinct researchers targeting non-US datasets or intraday alphas are unconditionally overwritten with session-level US equity defaults.

2. **Incomplete Persisted Settings Schema**:
   - Location: [`alpha_harness/db/models.py:L965-971`](backend/src/alpha_harness/db/models.py):
     ```python
     sim_region: Mapped[str] = mapped_column(String(32), default="USA")
     sim_universe: Mapped[str] = mapped_column(String(64), default="TOP3000")
     sim_neutralization: Mapped[str] = mapped_column(String(64), default="INDUSTRY")
     sim_decay: Mapped[int] = mapped_column(Integer, default=4)
     sim_delay: Mapped[int] = mapped_column(Integer, default=1)
     ```
   - Evidence: `ResearchCandidate` models only 5 simulation parameters. Critical BRAIN simulation parameters defined in [`SimulationSettings`](backend/src/alpha_harness/brain/schemas.py) — including `truncation` (0.08), `pasteurization` ("ON"), `unit_handling` ("VERIFY"), `nan_handling` ("ON"), `instrument_type` ("EQUITY"), `max_trade`, `max_position`, and `simulation_mode` — are not modeled or persisted on `ResearchCandidate`.
   - Result: Exact reproduction and auditability are broken because ambient platform defaults are applied during execution but never recorded with the candidate.

3. **Absence of Preflight Dataset Compatibility Validation**:
   - Location: [`alpha_harness/orchestrator/researchers.py:L336-430`](backend/src/alpha_harness/orchestrator/researchers.py):
   - Evidence: When an LLM researcher selects a dataset (`target_dataset_id`), there is no validation against [`DatafieldCatalog.coverage`](backend/src/alpha_harness/discovery/catalog.py) or `DiscoveredDataset`. If an Asian or European dataset is selected, the candidate is created with `USA`/`TOP3000`, leading to simulation failure or invalid execution.

4. **Lack of Dynamic Platform Schema Validation**:
   - Location: [`alpha_harness/brain/settings_schema.py:L21-50`](backend/src/alpha_harness/brain/settings_schema.py):
   - Evidence: The platform exposes recursive legal choices via `OPTIONS /simulations` parsed by `resolve_choices`. However, candidate dispatch in the orchestrator does not invoke `resolve_choices` before queuing simulations. Invalid setting combinations (e.g., a universe unavailable in a selected region) fail only asynchronously at the simulation execution boundary.

### 1.2 Hypotheses (Requiring Pre-Implementation Verification)
- *Hypothesis 1*: Candidate ideas generated by LLMs may occasionally propose custom truncation (e.g. `0.01` or `0.05`) or custom neutralization (`SUBINDUSTRY` or `SECTOR`).
- *Hypothesis 2*: Some datasets require specific `delay` values (e.g. `0` for intraday/tick data) that conflict with the session-level `delay=1`.

## 2. Minimal Remediation Plan for P1-15

### 2.1 Explicit Simulation Configuration Data Model
Introduce a validated `CandidateSimulationSettings` dataclass and JSON storage:
```python
@dataclass(slots=True)
class CandidateSimulationSettings:
    region: str
    universe: str
    neutralization: str
    decay: int
    delay: int
    instrument_type: str = "EQUITY"
    truncation: float = 0.08
    pasteurization: str = "ON"
    unit_handling: str = "VERIFY"
    nan_handling: str = "ON"
    max_trade: float | None = None
    max_position: float | None = None
    simulation_mode: str | None = None
    language: str = "FASTEXPR"
    raw_settings: dict[str, Any] = field(default_factory=dict)
```

### 2.2 Database Persistence Updates
1. Add `simulation_settings: Mapped[dict[str, Any] | None] = mapped_column(JSON, nullable=True)` to `ResearchCandidate`.
2. Add `settings_hash: Mapped[str | None] = mapped_column(String(64), nullable=True)` to track the SHA-256 fingerprint of the simulation configuration for deterministic reproduction.
3. Keep existing scalar columns (`sim_region`, `sim_universe`, `sim_neutralization`, `sim_decay`, `sim_delay`) populated as denormalized accessors for backward compatibility.

### 2.3 Preflight Settings Validation Gate
In [`alpha_harness.orchestrator.researchers`](backend/src/alpha_harness/orchestrator/researchers.py):
1. **Candidate-Level Overrides**: Allow researcher ideas to specify candidate-level settings (`region`, `universe`, `decay`, `neutralization`, `delay`, `truncation`) with explicit validation.
2. **Dataset Compatibility Gate**: Cross-reference candidate settings against `DatafieldCatalog` / `DiscoveredDataset` coverage (region, universe, delay). If incompatible, reject early with explicit error code (`ERR_SIMULATION_SETTINGS_INCOMPATIBLE_WITH_DATASET`).
3. **Platform Options Gate**: Validate settings against `settings_schema.resolve_choices` before queuing.

### 2.4 Simulation Dispatch Wiring
Ensure that when `SimulationSettings` is constructed for BRAIN dispatch, it uses the candidate's persisted `simulation_settings` dictionary rather than ambient defaults.

## 3. Explicit Acceptance Criteria & Required Regression Tests

### 3.1 Acceptance Criteria
1. **Explicit Persistence**: Every simulated `ResearchCandidate` records its complete, validated simulation settings in `simulation_settings` JSON column, including `truncation`, `pasteurization`, `unit_handling`, `nan_handling`, and `instrument_type`.
2. **Deterministic Fingerprint**: `settings_hash` contains SHA-256 digest of canonicalized settings dictionary.
3. **Candidate-Level Overrides**: An LLM idea proposing valid custom settings (e.g. `decay=2`, `neutralization="SECTOR"`, `truncation=0.05`) overrides session-level defaults without being silently overwritten.
4. **Preflight Validation**: Incompatible settings (e.g., non-existent universe in region, or dataset region mismatch) fail preflight before dispatch with clear diagnostic reasons, without consuming a simulation execution slot.
5. **No Silent Fallbacks**: If required settings are missing and cannot be derived from a valid profile, candidate validation raises a configuration error rather than silently defaulting to `"USA"` / `"TOP3000"`.

### 3.2 Required Regression Tests (`tests/test_p1_15_simulation_settings.py`)
1. `test_candidate_persists_complete_simulation_settings`: Verifies all settings (including truncation, pasteurization, unit_handling) are stored in `simulation_settings` and `settings_hash` is computed.
2. `test_candidate_level_override_preserves_custom_settings`: Proves a researcher idea with custom decay/neutralization retains its settings.
3. `test_dataset_region_mismatch_rejected_in_preflight`: Candidate using European dataset with US region setting is rejected before simulation dispatch.
4. `test_invalid_universe_for_region_rejected_by_schema`: Rejects combinations that fail `settings_schema.resolve_choices`.
5. `test_backward_compatibility_existing_candidates`: Legacy rows without JSON settings load smoothly and fall back to scalar columns.
6. `test_provenance_hash_incorporates_simulation_settings`: Changing simulation settings alters the candidate provenance fingerprint.

## 4. Architectural Interactions & Dependencies

### 4.1 Interaction with P0-03 Holdout Isolation
- Preflight validation of candidate simulation settings must **never** inspect or depend on holdout period data (`holdout_start`, `holdout_end`).
- Settings validation operates purely on metadata (dataset coverage, region, universe legality). Holdout dates remain strictly quarantined.

### 4.2 Interaction with P0-02 Provenance Integrity
- `settings_hash` must be incorporated into candidate provenance hashing (`provenance_hash`). If simulation settings differ (e.g. `decay=2` vs `decay=4`), the candidate has a distinct provenance identity, preventing parameter drift.

### 4.3 Interaction with P1-14 Diversity Selection
- Diversity grouping and deduplication (`DiversitySelector`) cluster on AST skeletons and expression hashes. When comparing candidate diversity across different universes or regions, `simulation_settings` must be preserved as part of the candidate cohort tuple.
